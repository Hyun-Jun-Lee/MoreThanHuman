# tomatalk 마케팅 전략

> 작성: 2026-10-23 · 버전: 1.0 · 상태: 고객·채널 검증 전 실행안
> 제품 기준: [STRATEGY.md](../../STRATEGY.md) · 대상: 한국어→영어 우선 가설, 영어→한국어 검증 고객군

## 1. 목표와 판단 기준

tomatalk의 첫 마케팅 과제는 설치 수를 크게 만드는 일이 아니라 **누가 첫 발화를 마치고 일주일 뒤에도 다시 대화하는지** 확인하는 일이에요. 한국어 사용자 영어 학습을 우선 가설로 두고, 영어 설명을 이해하는 한국어 학습자는 같은 방식으로 작게 검증해요. 두 고객군의 메시지·유입·첫 사용·재대화 결과를 섞어 보고하지 않아요.

이 문서는 저장소의 현재 구현과 공개된 경쟁사·플랫폼 설명에 근거해요. 고객 인터뷰 원문, 유입 성과, 실제 운영 서버 설정, 앱스토어 출시 상태, 판매 가격, 사용 가능한 예산은 확인되지 않았어요. 따라서 고객 문제·차별점·채널 우선순위는 **검증할 가설**이에요. 숫자는 시장 평균이나 매출 예측이 아니라 작은 실험의 범위와 중단 기준이에요.

### 제품에서 확인한 경험과 홍보 조건

| 경험 | 보여줄 장면 | 안내 조건 |
|---|---|---|
| 홈의 주간 추천 주제 | 주제 선택 → AI의 첫 질문 → 학습자의 첫 답변 | 운영자가 발행한 묶음이 있어야 보여요. 매일 새 주제가 나온다고 약속하지 않아요. |
| 직접 고른 주제와 Topic Prep | 관심사 입력 → 검색 기반 준비 카드 → 대화 | 검색 자료가 충분하지 않으면 주제를 다시 고르는 안내가 나올 수 있어요. 모든 대화가 웹 검색을 쓰는 것은 아니에요. |
| 상황별·직접 입력 롤플레이 | 실제 상황 선택 → 추가 질문에 답하기 | 현재 앱의 시나리오와 실제 응답으로 시연해요. |
| 글·음성 대화와 문장별 음성 응답 | 첫 문장이 화면에 나타나고 음성으로 재생되는 과정 | 문장별 스트리밍이에요. 완전 실시간 통화·발음 점수로 소개하지 않아요. 실기기 품질은 배포 전 확인해요. |
| 문법 피드백 | 학습자 문장 → 교정·설명 → 다시 말하기 | 피드백은 비동기로 도착하며 지연·실패할 수 있어요. 즉시 교정을 보장하지 않아요. |
| 토마토 바구니 언어 스낵 | 홈에서 표현을 열어 짧게 학습하기 | 기기 로컬 날짜의 바구니이며, 매일 새로운 콘텐츠 12개가 발행되는 구조는 아니에요. |

앱은 현재 한국어 설명으로 영어 학습, 영어 설명으로 한국어 학습을 선택할 수 있어요. 중국어가 포함된 언어쌍은 모바일에서 선택할 수 없어요. 구독 화면과 iOS 구매·복원 경로는 구현됐지만 서버의 대화 권한 스위치는 기본적으로 꺼져 있어요. 무료 사용 한도·상품·가격을 광고나 소개 페이지에 쓰기 전 운영 설정과 App Store Connect 상품 상태를 확인해요. [대화 권한 계약](../_contracts/CONVERSATION_ACCESS.md), [운영 절차](../../docs/OPERATIONS.md#대화-이용-권한-활성화)를 기준으로 해요.

## 2. 고객 조사: 먼저 확인할 일

| 고객군 | 현재 가설 | 기존 대안과 확인할 상황 |
|---|---|---|
| 한국어 사용자 영어 학습 | 기본 문장은 알지만 관심사를 두고 두세 문장 이상 말하기 어려운 성인 | 교재·강의로 배운 표현을 실제로 써 본 시점, 회화 모임·튜터·범용 AI를 쓰거나 그만둔 이유 |
| 영어 설명을 이해하는 한국어 학습 | 한글·기초 문장을 알지만 한국 방문·생활 또는 관심사 대화의 후속 질문에 막히는 성인 | 실제 상황을 준비한 계기, 교사·영상·회화 앱을 쓴 과정과 남은 불편 |

각 고객군에서 대표 사용자 최소 5명에게 20\~30분 동안 **최근에 말하기 연습이 필요했던 실제 사건**을 물어요. 무엇을 먼저 시도했고, 어떤 순간에 그만두거나 다른 방법으로 옮겼는지, 실제로 돈이나 시간을 썼는지 기록해요. 같은 사람에게 현재 앱으로 주간 추천·직접 입력·롤플레이 중 한 경로를 처음 사용하게 하고 어디서 멈추는지 관찰해요. “쓸 것 같아요”, “구독할게요” 같은 가정형 응답을 사용·구매 증거로 세지 않아요.

발언 원문, 문제 상황, 기존 대안, 전환 계기, 새 도구의 기대, 불안, 기존 습관을 고객군별로 보관해요. 공개 리뷰와 커뮤니티 글은 질문과 표현 후보를 찾는 자료이며 tomatalk 고객의 검증 결과로 취급하지 않아요. 현재 저장소에는 실제 고객 인터뷰나 정리된 고객 발언이 없으므로 페르소나의 동기와 구매 의향을 사실로 쓰지 않아요.

공개 발언에서 확인한 개별 사례와 두 고객군의 JTBD 가설, 인터뷰 질문은 [초기 고객 조사](CUSTOMER_RESEARCH.md)에 출처와 함께 정리했어요.

## 3. 포지셔닝 가설과 메시지

Speak는 관심 주제로 맞춤 말하기 수업과 자유로운 대화를 제공하고, Duolingo도 AI 대화 연습을 제공해요. 따라서 **AI와 관심사로 대화한다**는 말만으로 차별성을 주장할 수 없어요. [Speak Tutor 공식 안내](https://help.speak.com/en/articles/11396739-what-is-speak-tutor), [Duolingo 대화 기능 안내](https://blog.duolingo.com/video-call/)

tomatalk에서 검증할 가치는 **시작 방식을 고른 뒤 실제로 답변을 이어 가고 자신의 표현을 살펴보는 흐름**이에요. 검색 기반 관심사 준비, 바로 시작하는 추천, 상황별 롤플레이 중 어느 경로가 누구에게 더 가치 있는지는 첫 사용과 재대화로 판단해요. 경쟁 제품보다 학습 효과·응답 속도·가격이 낫다는 주장은 검증 전에는 사용하지 않아요.

| 학습자가 지금 쓰는 대안 | 비교할 상황 | tomatalk의 검증 후보 |
|---|---|---|
| 교재·강의 뒤 혼자 복습 | 배운 표현을 실제 대화로 옮기려는 순간 | 필요한 상황이나 관심사를 골라 첫 질문에 답하는 흐름 |
| 범용 AI 대화 | 주제와 연습 방식을 스스로 설정하는 과정 | 추천·준비 카드·롤플레이 중 맞는 시작 경로를 고르고 표현 피드백까지 보는 흐름 |
| 다른 회화 앱 또는 사람과의 연습 | 첫 발화까지의 시간, 이어 말하기, 다시 사용할 이유 | 고객이 실제 사용 후 꼽는 특정 경험만 가치 제안으로 채택 |

**포지셔닝 문장 가설:** “말할 주제를 정하거나 추천받아 AI의 질문에 답하고 내 표현을 돌아볼 수 있는 영어·한국어 회화 연습 앱.” 이 문장은 고객에게 보여줄 초안이며, 두 언어를 한 광고 문구에 함께 넣을 필요는 없어요. 고객군별 문구는 아래에서 따로 검증해요.

| 고객군 | 첫 메시지 후보 | 시연할 장면 | 확인할 반응 |
|---|---|---|---|
| 영어 학습 | “오늘 하고 싶은 이야기로 영어 대화를 시작해 보세요.” | 관심사 입력 또는 추천 주제 → 첫 답변 → 문법 피드백 | 주제 선택이 첫 발화를 쉽게 만드는지, 다음 날 다시 말할 이유가 생기는지 |
| 한국어 학습 | “Practice the Korean conversation you need next.” | 생활 상황 롤플레이 → 추가 질문에 답하기 → 표현 확인 | 자신의 실제 상황으로 받아들이는지, 영어 설명이 충분한지 |

각 메시지는 고객의 실제 표현과 관찰 결과로 다시 써요. 소개 문구의 근거가 된 발언과 제품 장면을 함께 보관해요. “AI”, “개인화”, “자신감 향상” 같은 추상적인 단어만으로 제목을 만들지 않아요.

## 4. 모집 경로와 콘텐츠

초기에는 두 경로만 운영해요. **첫째, 학습 모임·교사·소규모 교육 크리에이터를 통한 직접 모집**으로 실제 첫 사용을 관찰해요. 접근 가능한 모임 한두 곳에서 운영 규칙을 확인하고, 참여자가 직접 연습할 상황을 제시해요. 무작위 대량 메시지는 사용하지 않아요.

**둘째, 실제 앱 사용 장면을 담은 짧은 영상**으로 두 메시지를 시험해요. 영상은 막히는 상황 → 제품의 한 시작 경로 → 학습자의 답변 → 피드백 순서로 만들어요. 고객군별 링크와 소재 ID를 분리해요. 음성·대기 시간을 편집하면 편집 사실을 밝히고, 시연용 대화는 데모로 표시해요. 후기·대화 캡처는 당사자 동의를 받은 경우만 사용해요.

출시 후에는 언어별 앱스토어 페이지와 캠페인 링크를 시험할 수 있어요. Apple의 Custom Product Pages는 고객군별 스크린샷·문구와 성과 비교를 지원하지만, 실제 앱 배포와 페이지 준비가 선행돼야 해요. [Apple 공식 안내](https://developer.apple.com/help/app-store-connect-analytics/acquisition/custom-product-pages)

유료 광고와 유료 크리에이터 협업은 첫 대화·재대화와 운영 예산이 확인된 뒤 별도 상한을 정해 시작해요. 현재 확정된 예산이 없으므로 이 문서는 지출을 전제로 성과 목표를 계산하지 않아요.

## 5. 첫 90일 실행안

시작일은 베타 배포 방식과 담당자가 정해진 날이에요. 서비스 책임자가 임시 담당자이며 실제 실행 전에 인터뷰·콘텐츠·계측 담당자를 한 명씩 지정해요.

**90일 목표:** 우선 고객군에서 모집부터 첫 발화와 7일 재대화까지 이어지는 경로를 찾는 것이에요. 판단할 결과는 (1) 고객군별 최소 5명의 실제 사건 인터뷰와 첫 사용 관찰, (2) 두 모집 경로에서 각각 적합한 첫 사용자 최소 5명 확보, (3) 우선 고객군에서 관찰 기간을 마친 활성 사용자 최소 10명의 7일 재대화 분자·분모와 이탈 이유 확보예요. 세 번째 표본에서 3명 이상이 재대화하면 더 큰 모집 실험을 검토하고, 그보다 적으면 제품 경험과 고객 문제를 다시 살펴봐요. **3/10은 확장 검토를 위한 임시 기준이지 업계 평균이나 제품 적합성의 증거가 아니에요.**

| 기간 | 실행 | 다음 단계로 넘어갈 근거 |
|---|---|---|
| 1\~30일: 문제·첫 사용 확인 | 고객군별 인터뷰 최소 5명, 첫 사용 관찰, 실제 iOS·Android 대화·음성·피드백 점검, 유입·첫 발화 장부 준비 | 반복되는 문제와 막힌 단계, 고객 발언에 근거한 메시지 1개씩, 시연 가능한 경로 |
| 31\~60일: 두 경로 소규모 실험 | 모임·교사 경로와 짧은 영상 경로를 각각 운영, 고객군·소재별 첫 사용과 7일 재대화 기록 | 유입 수뿐 아니라 첫 발화·3회 대화·재대화의 분자와 분모, 투입 시간 |
| 61\~90일: 집중 또는 수정 | 반복 사용이 확인된 고객군·메시지·채널에 시간을 더 배분하고, 막힌 경로는 제품·메시지를 수정한 뒤 다시 관찰 | 같은 방향이 두 모집 차수에서 나타나는지, 다음 90일에 집중할 경로 |

초기 범위 제안은 **고객군별 관찰 사용자 10명, 채널별 시험 2주 또는 담당자 시간 8시간**이에요. 이는 통계적 우열 판정 표본이 아니라 운영 상한이에요. 관찰 사용자 5명 중 3명 이상이 같은 가입·첫 대화 단계에서 막히면 그 경로의 모집을 멈추고 원인을 고쳐요. 채널에 2주 또는 8시간을 썼는데 적합한 첫 사용자 5명에게도 닿지 못하면 메시지나 접점을 바꿔요. 클릭·설치가 있어도 첫 대화나 재대화가 없으면 광고비를 늘리지 않아요.

### 예산과 운영 상한

확정된 현금 예산과 인력 시간은 미확인이에요. 1\~30일은 보유 채널과 직접 관찰을 기본으로 하고 **유료 광고·유료 협업 집행액은 0원**으로 잡아요. 인터뷰 보상이나 제작비를 쓰려면 실행 전에 항목별 현금 상한, 담당자 시간, 종료 기준을 정해요. 31\~90일의 유료 집행 여부는 첫 사용·재대화 결과와 실제 가격·AI 사용 비용을 확인한 뒤 결정해요.

## 6. 측정 장부와 현재 공백

첫 사용 경로는 **유입 → 언어쌍 선택 → 로그인·계정 초기화 → 필수 닉네임 설정 → 추천·직접 입력·롤플레이 선택 → 첫 학습자 발화와 AI 응답 → 3회 대화 → 7일 재대화**로 봐요. 피드백 제공·열람과 구독 구매는 별도 단계예요. 추천 주제의 AI 첫 질문만 생성된 상태를 활성화로 세지 않아요.

| 지표 | 정의 | 현재 자료·필요한 작업 |
|---|---|---|
