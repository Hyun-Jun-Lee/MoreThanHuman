# tomatalk 마케팅 전략

> 작성: 2026-10-23 · 버전: 1.3 · 상태: 공개 출시 전후 60일 실행안
> 제품 기준: [STRATEGY.md](../../STRATEGY.md) · 대상: 한국어→영어 우선 가설, 영어→한국어 검증 고객군

## 1. 목표와 판단 기준

tomatalk의 첫 마케팅 과제는 설치 수를 크게 만드는 일이 아니라 **누가 첫 발화를 마치고 일주일 뒤에도 다시 대화하는지** 확인하는 일이에요. 한국어 사용자 영어 학습을 우선 가설로 두고, 영어 설명을 이해하는 한국어 학습자는 같은 방식으로 작게 검증해요. 두 고객군의 메시지·유입·첫 사용·재대화 결과를 섞어 보고하지 않아요.

첫 대외 메시지는 **“회화 공부는 하는데 정해진 학습 내용이 지금 내가 이야기할 주제와 다르다”**는 고객 상황에서 시작해요. tomatalk의 주제 선택과 첫 질문은 이 불편을 덜기 위한 방법으로 보여줘요. 한국어학습자에게는 소재 불일치 공개 사례가 한 건 있지만, 한국 영어학습자에게 같은 문제가 반복되는지는 아직 확인되지 않았어요. 해당 문제가 없거나 다른 앱의 맞춤 주제로 이미 해결된 고객에게 이 메시지를 적용하지 않아요.

이 문서는 저장소의 현재 구현, 공개된 경쟁사·플랫폼 설명, 사용자가 알려 준 **공개 출시 전제·2~3명·현금 30만~50만 원·직접 연락 가능한 학습자 5명 이상·기존 SNS 계정 없음**에 근거해요. 고객 인터뷰 원문, 유입 성과, 실제 스토어 공개일·운영 서버 설정·판매 가격·주당 가용 시간은 확인되지 않았어요. 따라서 고객 문제·차별점·채널 우선순위는 **검증할 가설**이에요. 숫자는 시장 평균이나 매출 예측이 아니라 작은 실험의 범위와 중단 기준이에요.

### 제품에서 확인한 경험과 홍보 조건

| 경험 | 보여줄 장면 | 안내 조건 |
|---|---|---|
| 홈의 주간 추천 주제 | 주제 선택 → AI의 첫 질문 → 학습자의 첫 답변 | 운영자가 발행한 묶음이 있어야 보여요. 매일 새 주제가 나온다고 약속하지 않아요. |
| 직접 고른 주제와 Topic Prep | 관심사 입력 → 검색 기반 준비 카드 → 대화 | 검색 자료가 충분하지 않으면 주제를 다시 고르는 안내가 나올 수 있어요. 모든 대화가 웹 검색을 쓰는 것은 아니에요. |
| 상황별·직접 입력 롤플레이 | 실제 상황 선택 → 추가 질문에 답하기 | 현재 앱의 시나리오와 실제 응답으로 시연해요. |
| 글·음성 대화와 문장별 음성 응답 | 첫 문장이 화면에 나타나고 음성으로 재생되는 과정 | 문장별 스트리밍이에요. 완전 실시간 통화·발음 점수로 소개하지 않아요. 실기기 품질은 배포 전 확인해요. |
| 문법 피드백 | 학습자 문장 → 교정·설명 → 다시 말하기 | 피드백은 비동기로 도착하며 지연·실패할 수 있어요. 즉시 교정을 보장하지 않아요. |
| 토마토 바구니 언어 스낵 | 홈에서 표현을 열어 짧게 학습하기 | 기기 로컬 날짜의 바구니이며, 매일 새로운 콘텐츠 12개가 발행되는 구조는 아니에요. |

앱은 현재 한국어 설명으로 영어 학습, 영어 설명으로 한국어 학습을 선택할 수 있어요. 중국어가 포함된 언어쌍은 모바일에서 선택할 수 없어요. 구독 화면과 iOS 구매·복원 경로는 구현됐지만 서버의 대화 권한 스위치는 기본적으로 꺼져 있어요. 무료 사용 한도·상품·가격을 광고나 소개 페이지에 쓰기 전 운영 설정과 App Store Connect 상품 상태를 확인해요. [대화 권한 계약](../_contracts/CONVERSATION_ACCESS.md), [운영 절차](../../docs/OPERATIONS.md#대화-이용-권한-활성화)를 기준으로 해요.

## 2. 고객 조사: 먼저 확인할 일

| 고객군 | 현재 가설 | 기존 대안과 확인할 상황 |
|---|---|---|
| 한국어 사용자 영어 학습 | 기본 문장은 알지만 오늘 필요한 자기 주제로 첫 답변과 후속 답변을 하기 어려운 성인. 정해진 학습 소재와의 불일치는 미확인 가설 | 그날 말할 주제가 기존 수업·앱에 있었는지, 없었다면 무엇으로 준비했는지, 맞춤 주제 대안에서 남은 불편 |
| 영어 설명을 이해하는 한국어 학습 | 한글·기초 문장을 알지만 한국 방문·생활 또는 관심사 대화의 후속 질문에 막히는 성인 | 정해진 학습 장면이 실제 필요와 달랐는지, 교사·영상·회화 앱을 쓴 과정과 남은 불편 |

각 고객군에서 대표 사용자 최소 5명에게 20\~30분 동안 **최근에 말하기 연습이 필요했던 실제 사건**을 물어요. 무엇을 먼저 시도했고, 어떤 순간에 그만두거나 다른 방법으로 옮겼는지, 실제로 돈이나 시간을 썼는지 기록해요. 같은 사람에게 현재 앱으로 주간 추천·직접 입력·롤플레이 중 한 경로를 처음 사용하게 하고 어디서 멈추는지 관찰해요. “쓸 것 같아요”, “구독할게요” 같은 가정형 응답을 사용·구매 증거로 세지 않아요.

발언 원문, 문제 상황, 기존 대안, 전환 계기, 새 도구의 기대, 불안, 기존 습관을 고객군별로 보관해요. 공개 리뷰와 커뮤니티 글은 질문과 표현 후보를 찾는 자료이며 tomatalk 고객의 검증 결과로 취급하지 않아요. 현재 저장소에는 실제 고객 인터뷰나 정리된 고객 발언이 없으므로 페르소나의 동기와 구매 의향을 사실로 쓰지 않아요.

공개 발언에서 확인한 개별 사례와 두 고객군의 JTBD 가설, 인터뷰 질문은 [초기 고객 조사](CUSTOMER_RESEARCH.md)에 출처와 함께 정리했어요.

## 3. 포지셔닝 가설과 메시지

포지셔닝의 기준 문서는 [POSITIONING.md](POSITIONING.md)예요. 범주는 기존 **AI 회화 연습 앱**으로 두고, 첫 메시지에서는 **정해진 학습 내용에 오늘 필요한 이야기가 없었던 상황**을 먼저 보여줘요. 이어서 학습자가 자기 주제를 고르고 첫 질문의 도움을 받아 답변을 이어 가는 장면을 보여줘요. 이것이 고객에게 실제 불편인지, 경쟁 대안보다 더 가치 있는지는 검증 전이에요.

Speak는 관심 주제로 맞춤 말하기 수업과 자유로운 대화·롤플레이를 제공해요. Duolingo도 AI 대화 연습을 제공해요. 따라서 **기존 앱은 모두 정해진 커리큘럼뿐이다** 또는 **AI와 관심사로 대화한다**는 말로 차별성을 주장할 수 없어요. 소재 불일치를 겪은 고객이 지금 쓰는 대안에서 무엇을 못 했는지부터 확인해요. [Speak Tutor 공식 안내](https://help.speak.com/en/articles/11396739-what-is-speak-tutor), [Speak Free Talk 안내](https://help.speak.com/en/articles/13182402-free-talk-immersive-roleplay), [Duolingo 대화 기능 안내](https://blog.duolingo.com/duolingo-max/)

tomatalk에서 검증할 가치는 **오늘 필요한 자기 주제로 연습할 선택권과, 그 주제에서 첫 답변·다음 답변으로 이어지는 도움**이에요. 이는 직접 고른 주제 경로의 첫 메시지 후보예요. 검색 기반 준비, 바로 시작하는 추천, 상황별 롤플레이 중 어느 경로가 누구에게 더 가치 있는지는 첫 사용과 재대화로 판단해요. 이 행동 지표를 실제 현장의 말문 막힘 해소나 회화 실력 향상의 직접 증거로 부르지 않아요. 경쟁 제품보다 학습 효과·응답 속도·가격이 낫다는 주장은 검증 전에는 사용하지 않아요.

| 학습자가 지금 쓰는 대안 | 비교할 상황 | tomatalk의 검증 후보 |
|---|---|---|
| 정해진 교재·강의 뒤 혼자 복습 | 오늘 필요한 이야기가 배운 장면에 없을 때 | 자기 주제를 고르고 첫 질문의 도움으로 답변을 시작하는 흐름 |
| 범용 AI 대화 | 주제와 연습 방식을 스스로 설정하는 과정 | 추천·준비 카드·롤플레이 중 맞는 시작 경로를 고르고 표현 피드백까지 보는 흐름 |
| 다른 회화 앱 또는 사람과의 연습 | 첫 발화까지의 시간, 이어 말하기, 다시 사용할 이유 | 고객이 실제 사용 후 꼽는 특정 경험만 가치 제안으로 채택 |

**포지셔닝 문장 가설:** “정해진 학습 내용이 오늘 말하고 싶은 이야기와 맞지 않거나 자기 주제로 첫 문장을 꺼내기 어려운 학습자에게, tomatalk은 지금 필요한 주제를 고르고 첫 질문의 도움을 받아 답변을 이어 가게 하는 AI 회화 연습 앱이에요.” 이는 내부 전략 문장이며, 고객군별 광고에는 한 언어와 직접 고른 주제의 실제 장면만 보여줘요.

| 고객군 | 첫 메시지 후보 | 시연할 장면 | 확인할 반응 |
|---|---|---|---|
| 영어 학습 | “배운 대화와 지금 하고 싶은 이야기가 다른가요? 오늘 필요한 내 주제로 영어 대화를 연습해 보세요.” | 실제 필요했던 주제 → 직접 입력 → 준비 카드·첫 질문 → 답변·후속 대화 | 기존 학습 소재와의 불일치가 실제 문제인지, 질문 지원이 첫 발화와 다음 답변에 도움이 되는지 |
| 한국어 학습 | “Need to talk about something your lessons haven't covered? Practice it in Korean, starting with a question.” | 실제 필요했던 주제 → 직접 입력 → 첫 질문 → 한국어 답변·후속 대화 | 정해진 소재 불일치가 반복되는지, 자기 주제와 영어 설명이 충분한지, 다시 연습하는지 |

각 메시지는 고객의 실제 표현과 관찰 결과로 다시 써요. 소개 문구의 근거가 된 발언과 제품 장면을 함께 보관해요. “AI”, “개인화”, “자신감 향상”, “무제한 자유” 같은 추상적이거나 범위를 넘는 단어만으로 제목을 만들지 않아요. 정해진 소재에 불편이 없던 사람에게는 이 문제를 억지로 적용하지 않아요.

인터뷰와 짧은 영상에서는 위 **소재 불일치 문구**와 “오늘 필요한 내 주제로 대화를 연습해 보세요”처럼 불편을 전제하지 않는 문구를 함께 시험해요. 클릭만 보지 않고 각 문구를 본 사람이 자기 최근 상황으로 받아들이는지, 실제로 고른 주제가 무엇인지, 첫 답변·후속 답변까지 갔는지를 기록해요. 작은 표본의 반응을 곧바로 메시지 우위로 단정하지 않아요.

## 4. 모집 경로와 콘텐츠

초기에는 두 경로만 운영해요. **첫째, 현재 연락 가능한 학습자에게 직접 연락하고 소개를 받는 경로**에서 실제 말하기 사건과 첫 사용을 관찰해요. 동의한 사람에게만 설치 링크와 후속 질문을 보내고, 무작위 대량 메시지는 사용하지 않아요.

**둘째, 교사·학습 모임 운영자가 허용한 체험 자리**에서 참여자가 자기 주제로 답해 보게 해요. 운영 중인 SNS 계정이 없으므로 새 계정의 조회 수를 60일 핵심 성과로 두지 않아요. 짧은 영상은 두 경로에서 쓰는 시연 자료예요. 영상은 **오늘 필요한 이야기가 정해진 연습 소재에 없는 상황 → 자기 주제 입력 → 첫 질문의 도움 → 학습자의 답변과 후속 대화** 순서로 만들어요. 피드백은 실제 도착한 장면이 있을 때만 덧붙여요. 음성·대기 시간을 편집하면 편집 사실을 밝히고, 시연용 대화는 데모로 표시해요. 후기·대화 캡처는 당사자 동의를 받은 경우만 사용해요.

출시 후에는 언어별 앱스토어 페이지와 캠페인 링크를 시험할 수 있어요. Apple의 Custom Product Pages는 고객군별 스크린샷·문구와 성과 비교를 지원하지만, 실제 앱 배포와 페이지 준비가 선행돼야 해요. [Apple 공식 안내](https://developer.apple.com/help/app-store-connect-analytics/acquisition/custom-product-pages)

유료 광고·유료 게시·유료 크리에이터 협업은 첫 60일에 집행하지 않아요. 30만~50만 원의 현금 상한은 인터뷰 참여 보상과 추가 비교 모집에 배정해요. 집행 항목과 상한은 [초기 60일 실행안](GROWTH_PLAN_60D.md)에 있어요.

## 5. 초기 60일 실행안

실행의 기준일 D1은 실제 고객이 공개 스토어에서 설치하고 첫 대화를 완료할 수 있음을 확인한 날이에요. 공개가 늦어지면 인터뷰·시연 준비를 먼저 하고, 설치·재대화 60일 목표의 시계는 시작하지 않아요. 상세 일정과 단일 책임자, 예산, 중단 기준은 [growth-plan 기반 초기 60일 마케팅 실행안](GROWTH_PLAN_60D.md)을 기준으로 해요. 회의에서는 [60일 실행안 HTML](GROWTH_PLAN_60D.html)을 함께 볼 수 있어요.

**60일 목표:** (1) 두 고객군에서 최근 말하기 사건 인터뷰 각 5명 이상, (2) 두 경로에서 적합한 첫 사용자 20명 이상과 D52까지 첫 대화 완료 10명 이상, (3) D7 관찰 창이 끝난 첫 대화 사용자 10명 이상 중 재대화 3명 이상이에요. **3/10은 다음 모집 실험을 검토할 임시 기준이며 제품 적합성의 증거가 아니에요.**

| 기간 | 실행 | 다음 단계로 넘어갈 근거 |
|---|---|---|
| 1\~30일: 문제·첫 사용 확인 | 공개 설치와 첫 대화를 확인하고 고객군별 최근 사건 인터뷰 최소 5명, 첫 사용 관찰, 장부·시연 자료·교사/모임 제안을 준비해요. | 소재 불일치가 실제 문제인지, 막힌 제품 단계가 무엇인지, 허용된 체험 자리가 있는지 확인해요. |
| 31\~60일: 두 경로 소규모 실행 | 직접 연락·소개와 교사/모임 체험을 운영하고 문구·언어쌍·경로별 첫 대화와 7일 재대화를 기록해요. | 유입 수뿐 아니라 실제 첫 대화·재대화의 분자와 분모, 투입 시간·현금 사용액으로 다음 30일의 집중 또는 수정을 정해요. |

관찰 사용자 5명 중 3명 이상이 같은 가입·첫 대화 단계에서 막히면 모집 확장을 멈추고 원인을 고쳐요. 채널에 2주 또는 담당자 시간 8시간을 썼는데 적합한 첫 사용자 5명에게도 닿지 못하면 메시지나 접점을 바꿔요. 우선 영어학습자 5명 중 2명 미만이 유도 없이 소재 불일치를 실제 사건으로 설명하면 이 불편을 대표 메시지에서 내리고 다른 반복 문제를 찾아요. 모두 작은 표본의 **운영 판정**이에요.

### 예산과 운영 상한

현금 집행 기본 상한은 **30만 원**, 예비비까지 포함한 절대 상한은 **50만 원**이에요. 최초 인터뷰 10명 × 2만 원에 20만 원, 후속 인터뷰 최대 5명에 10만 원을 배정해요. 추가 비교 모집이 필요한 경우에만 예비비 20만 원을 열어요. 인터뷰 보상은 긍정 평가·재사용 여부와 무관하게 지급해요. 유료 광고·유료 게시·크리에이터비는 0원이에요. 주당 투입 시간은 사용자가 정하지 않았으므로 [실행안](GROWTH_PLAN_60D.md)의 주당 총 8시간은 제안 상한이에요.

## 6. 측정 장부와 현재 공백

첫 사용 경로는 **유입 → 언어쌍 선택 → 로그인·계정 초기화 → 필수 닉네임 설정 → 추천·직접 입력·롤플레이 선택 → 첫 학습자 발화와 AI 응답 → 3회 대화 → 7일 재대화**로 봐요. 피드백 제공·열람과 구독 구매는 별도 단계예요. 추천 주제의 AI 첫 질문만 생성된 상태를 활성화로 세지 않아요.

| 지표 | 정의 | 현재 자료·필요한 작업 |
|---|---|---|
| 첫 대화 활성화 | 신규 계정 중 24시간 내 학습자 발화와 해당 AI 응답을 마친 사람 / 신규 계정 | 계정·대화·메시지로 기본 집계 가능. 가입 단계별 이탈은 별도 이벤트가 필요해요. |
| 대화 지속 | 첫 대화 사용자 중 학습자 발화·AI 응답 3회를 마친 사람 / 첫 대화 사용자 | 메시지 기록으로 집계해요. |
| 7일 재대화 | 첫 활성화 후 6\~8일차에 다시 학습자 발화·AI 응답을 마친 사람 / 관찰 기간을 마친 활성 사용자 | 계정·대화·메시지 시각으로 집계해요. |
| 자기 주제 문제·가치 | 인터뷰에서 최근 필요한 주제와 기존 학습 소재의 불일치 여부, 대안 사용, 첫 사용에서 고른 주제와 도움 된 단계 | 고객 발언·최근 사건·관찰 기록을 고객군별로 보관해요. 앱 행동 지표만으로 불편 해소를 판정하지 않아요. |
| 경로별 결과 | 추천·직접 입력·롤플레이의 활성화와 재대화 | 일반 대화에 공통 시작 경로가 저장되지 않아요. 제품 이벤트 또는 영속 출처 필드가 필요해요. |
| 피드백 확인 | 피드백 도착과 오류 교정 설명을 실제로 펼친 상태를 분리 | 비동기 피드백의 도착과 설명 카드 펼침을 구분하는 이벤트가 필요해요. |
| 유지 사용자 확보 비용 | 채널 지출과 투입 시간 / 해당 채널의 7일 재대화 사용자 | 유입 출처와 계정의 연결, 비용 장부가 필요해요. 분모가 0이면 산출 불가로 표시해요. |

제품 내 유입 계측이 준비되기 전에는 참여 동의를 받은 작은 장부로 모집 차수·언어쌍·소재·첫 대화·재대화를 연결해요. 설치 전 링크의 UTM이 자동으로 앱 계정에 이어진다고 가정하지 않아요. 앱스토어 분석의 다운로드·유지는 앱 안의 첫 발화나 피드백 열람을 대체하지 않아요. [Apple App Analytics 안내](https://developer.apple.com/app-store-connect/analytics/)

## 7. 공개 실행 전 확인과 변경 기록

- 실제 앱 배포 방식, 스토어 출시 상태, 운영 서버의 대화 권한 스위치와 Apple 상품·가격을 확인해요.
- 주간 추천과 스낵 발행이 실제 운영 중인지 확인하고, 발행 실패·비어 있는 홈에서도 소개 문구가 사실인지 점검해요.
- 대표 기기에서 음성 입력·문장별 재생·비동기 피드백을 확인한 뒤 그 장면만 시연해요.
- 인터뷰 결과와 채널별 실제 첫 대화·재대화 수치를 반영해 고객군 우선순위, 문구, 시간·예산 상한을 갱신해요.
