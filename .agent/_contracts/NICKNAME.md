# 닉네임 설정 계약

> 상태: ACTIVE · 최종 갱신: 2026-11-23

- `profiles.name`은 Supabase에서 받은 기존 이름으로 유지해요. `profiles.nickname`은 별도 nullable 필드예요.
- migration 시 기존 프로필의 닉네임을 현재 이름으로 채워요. 새 프로필은 null로 만들어요.
- `GET /api/auth/me`의 `nickname: null`은 첫 설정이 완료되지 않은 상태예요. 앱은 로그인 또는 세션 복원 후 필수 팝업을 띄우고 저장 성공 전에는 닫지 않아요.
- 첫 설정 팝업의 입력 칸에는 기기의 우선 시스템 언어가 한국어면 영어 닉네임을, 영어 또는 그 밖의 언어면 한국어 닉네임을 무작위로 미리 채워요. 앱 표시 언어 설정과 학습 언어쌍은 추천 언어에 영향을 주지 않아요. 사용자는 추천값을 수정할 수 있고 저장할 때만 서버에 전송해요.
- `PUT /api/auth/me/nickname`은 인증된 본인의 닉네임만 저장하고 전체 `UserProfile`을 반환해요. 앞뒤 공백 제거와 NFC 정규화 후 1~20자이고 제어 문자는 허용하지 않아요. 다른 계정과 같은 값은 허용해요.
- 앱의 표시 이름과 아바타 이니셜에는 `nickname`을 우선 사용하고, 값이 없을 때만 `name`을 사용해요. 내 정보의 수정 팝업은 취소할 수 있어요.
- 자유 대화와 롤플레이의 생성 요청은 매번 현재 프로필의 `nickname`만 사용자 식별 정보로 전달해요. 닉네임은 대화 snapshot에 저장하지 않으므로 기존 대화도 다음 응답부터 최신 값을 사용해요.
- prompt는 닉네임을 지시가 아닌 구분된 데이터로 취급하고, 닉네임 안의 명령형 문구를 무시하도록 명시해요. AI는 인사·격려·화제 전환처럼 자연스러운 순간에만 닉네임을 간헐적으로 사용하며 매 응답에 반복하지 않아요. 이메일과 OAuth 원본 이름은 이 prompt context에 포함하지 않아요.
