# iOS Unread Reply Badge v1 — REVIEW

> 갱신: 2026-11-26 · 구현·자동 테스트·시뮬레이터 빌드 확인, 자동 회귀 보강 완료·사용자 수동 출시 검증 대기

## 서버

- `messages.read_at`은 nullable UTC 시각이에요. 기존 assistant 행은 migration `20261126_0002`에서 `created_at`으로 채우며 새 assistant 행은 null이에요. 사용자 메시지는 집계하지 않아요.
- `GET /api/conversations/unread/`는 Bearer 인증 후 `{success:true,data:{has_unread:bool}}`을 반환해요. 회원·관리자의 모든 소유 대화를 집계하고 슬롯·잔액·전송 가능 여부로 제한하지 않아요. 게스트는 항상 false예요.
- `POST /api/conversations/{id}/read/`는 `{message_ids:[UUID]}`를 받아요. 한 번에 1개부터 100개까지 허용하고, 본인 소유 대화의 명시된 assistant 메시지만 멱등하게 읽음으로 바꿔요. 타 계정 대화는 404, 잠긴 게스트 대화는 409예요. 타 대화 ID·사용자 메시지 ID는 무시해요. 성공 응답은 갱신된 전역 `has_unread`예요.
- 읽음은 AI 처리 동의·배지 사용 여부와 독립적이에요. 게스트도 열람 가능한 답변은 읽음으로 기록하므로 회원 전환 후 이미 본 답변이 배지를 만들지 않아요.

## Flutter

- 전경의 현재 대화 경로에 서버 ID가 확정된 AI 답변 전체가 공개된 프레임 뒤 명시적 ID를 묶어 전송해요. 스크롤 위치·말풍선 높이·체류 시간을 검사하지 않아요. 임시 메시지와 음성 순서에 따라 아직 일부만 공개된 답변은 제외해요. 마지막 문장 공개 후 마지막 음성 종료는 기다리지 않아요.
- 읽음·배지 처리는 답변 표시·오디오·다음 전송과 독립적이에요. 실패는 대화 오류가 되지 않고 다음 공개·복귀에서 재시도해요.
- `BadgeSyncController`가 계정 ID와 회원/게스트 유형, 동기화 세대를 검사해요. 읽음·삭제 시작은 이전 조회를 무효화하고 겹친 변경 후 재조회해요. native 쓰기를 직렬화하고 계정 변경은 이전 쓰기 뒤 지우기를 예약해요.
- 완료 여부를 놓친 요청만 캐시에 요청 ID를 남기고 대화 재진입·앱 복귀 시 상태 조회해요. 완료면 최신 페이지를 정식 ID로 병합하며 기존 과거 메시지를 보존해요. 진행 중·조회 실패는 다음 확인까지 남겨요. 정상 스트림과 복구 조회는 겹치지 않으며 일반 복귀에는 메시지를 추가 조회하지 않아요.

## 회원 선택과 iOS

- 회원 홈의 개인정보 안내·필수 닉네임 이후 별도 배지 선택을 표시해요. 선택은 기기 저장소의 회원 ID별로 저장하고 회원 프로필에서 변경해요. 게스트는 선택·설정·권한 요청 대상이 아니에요.
- iOS 16 이상에서만 `com.morethanhuman.curitalk/badge` MethodChannel을 사용해요. `status`, `request`, `set`(0/1), `settings`를 제공해요. 권한은 `.badge`만 요청하고 배너·소리·원격 푸시는 추가하지 않아요.
- 미결정 권한은 사용자가 사용을 선택했을 때만 요청해요. 거부 상태에서는 시스템 설정 진입을 안내하고 창을 재요청하지 않아요. Android·iOS 15에서는 미지원이에요.
- 앱 실행·복귀·답변 완료·읽음·삭제·계정 변경에 동기화해요. 앱 종료 중 실시간 갱신과 다기기 동기화는 범위 밖이에요.
