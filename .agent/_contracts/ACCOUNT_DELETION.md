# 계정 삭제와 구매 재전송 차단 v2 — REVIEW

> 2026-11-25

## 확정 정책

- 로그인한 사용자는 앱 안에서 계정 삭제를 요청할 수 있어요.
- 요청을 수락하면 계정의 앱 접근을 즉시 막아요. 모든 필수 삭제가 끝나기 전에는 완료라고 표시하지 않아요.
- 프로필·대화·학습 기록·사용자별 스낵 진행·음성 캐시·기기 위젯 상태는 복원 없이 삭제해요.
- 계정 삭제 시 추가 슬롯과 모든 턴을 영구 소멸시켜요. 재가입·다른 계정으로 복원하거나 이전하지 않아요.
- 같은 계정의 기기 변경은 서버 잔액을 조회해요. 재가입은 새 회원 체험 10턴만 받아요.
- 수동 부여 권한과 그 계정의 부여 이력은 계정 삭제 때 함께 지워요. 삭제된 관리자가 다른 계정에 부여한 기록에서는 관리자 ID를 비워요.
- 관리자 웹 세션과 코드 실패 기록은 사용자 계정에 연결되지 않아요. 계정 삭제는 해당 계정의 앱 접근과 학습 데이터를 처리하며 공유 코드 세션은 별도로 만료하거나 로그아웃해요.
- Supabase 익명 게스트도 Login 화면의 보조 동작에서 같은 삭제 계약을 사용할 수 있어요. 게스트 삭제는 동의, 누적 발화 원장, 이전 영수증과 인앱 로컬 캐시를 함께 지우며 완료 직후 새 익명 계정을 자동 생성하지 않아요.
- 회원으로 전환하지 않은 게스트는 마지막 성공 bootstrap 또는 AI 활동 30일 뒤 삭제 후보가 돼요. 정리 작업은 잠금 아래 `is_guest`와 마지막 활동 시각을 다시 확인하고 이 삭제 파이프라인을 호출해요. 회원 전환 또는 경계 직전 활동이 확인되면 제외해요.

## API 계약

- `DELETE /api/auth/me`: Supabase Bearer 인증, 본인 계정만 삭제해요. 요청을 영속화한 즉시 해당 계정의 보호 API 접근을 차단해요. 응답에는 서버가 생성한 영수증과 `apple_disconnect_required`가 있고, 필수 외부 작업이 완료되면 `completed`, 남으면 HTTP 202와 `processing`을 반환해요.
- `GET /api/auth/deletion-status/{receipt}`: 인증 없이 고엔트로피 영수증으로 `processing` 또는 `completed`만 반환해요. 이메일·계정 ID·삭제 자료는 반환하지 않아요.
- `POST /api/billing/apple/terminalize/`: 인증 없이 Apple JWS와 삭제 account token HMAC을 확인하고 지급 없이 거래를 종료해요.

## 실패와 데이터 처리

- 삭제 요청·재시도 상태는 별도 최소 기록에 저장해요. 서버 작업은 중복 실행해도 안전해야 하고, 실패한 단계는 운영 작업으로 재시도해요.
- 기존 Supabase JWT는 사용자 삭제 후 만료 전까지 유효할 수 있으므로 모든 보호 API는 삭제 요청 기록을 확인해요. 이전 토큰으로 프로필을 다시 만들 수 없어야 해요.
- Apple 로그인 계정은 삭제 직전에 재인증해 토큰 폐기에 사용할 코드를 받아요. 설정 또는 외부 장애로 폐기할 수 없으면 Apple의 수동 연결 해제 경로를 안내하고, 계정 데이터 삭제는 계속 진행해요.
- 삭제 완료 후 원문 user ID·account token·transaction ID는 남기지 않아요. 거래·계정·사용자 ID HMAC, terminal 상태, key version, 감사 시각과 삭제 영수증 해시만 분리 보관해 재지급·과거 JWT 접근을 막아요. HMAC keyring이 없으면 삭제를 시작하지 않아요.
