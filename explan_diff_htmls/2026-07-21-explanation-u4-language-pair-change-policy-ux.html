언어쌍 변경의 적용 범위를 사용자가 보게 만든 작업

U4는 새 기능을 크게 추가한 작업이 아니라, 이미 존재하는 profile default와 conversation snapshot의 차이를 UX에 드러낸 작업이에요. 사용자는 설정을 바꾸기 전에 “새 대화부터 적용된다”는 규칙을 볼 수 있습니다.

Background

언어쌍에는 두 종류의 상태가 있습니다. 하나는 profile preference이고, 다른 하나는 conversation snapshot이에요. 사용자는 전자를 바꾸지만, 이미 시작된 대화는 후자를 기준으로 계속 흘러갑니다.

이 정책 자체는 이미 시스템에 존재했습니다. Account sheet는 preference를 저장한 뒤 session을 복원하고 Home badge를 갱신합니다. Backend는 conversation 시작 시점의 language context를 conversation에 저장하고, 기존 conversation continuation은 그 snapshot을 사용합니다. 문제는 이 제품 규칙이 화면에 충분히 보이지 않았다는 점이에요.

U4의 제품 문장 언어쌍 변경은 새 대화부터 적용돼요. 기존 대화는 시작할 때 선택한 언어쌍을 유지해요.

Profile default

앞으로 시작할 Free Chat, Roleplay, Topic Prep handoff의 기본 언어쌍입니다.

Conversation snapshot

이미 시작된 대화가 계속 사용하는 생성 시점의 언어쌍입니다.

Account sheet

preference를 바꾸는 곳이므로 정책 copy가 가장 가까이 놓입니다.

Intuition

사용자는 설정을 바꾸면 “앱 전체가 즉시 바뀐다”고 생각하기 쉽습니다. 하지만 회화 학습에서 진행 중인 대화의 언어를 중간에 바꾸면 history, prompt, grammar feedback의 의미가 흐려질 수 있어요. 그래서 기존 대화는 snapshot을 유지하고, 새 대화부터 새 preference를 씁니다.

이전

selector와 save button은 있지만, 저장 후 기존 대화가 왜 그대로인지 설명하지 않았습니다.

이후

selector 근처에 compact helper copy가 있고, save 실패 시에도 정책 안내는 그대로 남습니다.

Code

1. 정책 copy를 language domain helper로 추가한다

U1의 helper 패턴을 이어서, locale별 문장을 `LearningLanguageContext`에 좁게 추가했습니다. 이 helper는 데이터 모델을 바꾸지 않고 표시 문장만 제공합니다.

String preferenceChangePolicyText(String localeCode) {
  return switch (localeCode) {
    'ko' => '새 대화부터 적용돼요. 기존 대화는 시작할 때 선택한 언어쌍을 유지해요.',
    'zh' => '适用于新对话。现有对话会保留开始时的语言组合。',
    _ =>
      'Applies to new conversations. Existing conversations keep the language pair they started with.',
  };
}

2. Account sheet에서 selector 바로 위에 보여준다

정책 문장은 warning modal이 아니라 context note입니다. 그래서 기존 `AppSectionLabel('Language Pair')` 아래, selector 위에 작은 텍스트로 들어갑니다.

const AppSectionLabel('Language Pair'),
const SizedBox(height: AppSpacing.xs),
Text(
  selectedLanguage.preferenceChangePolicyText(localeCode),
  style: AppTypography.bodySm.copyWith(
    color: Theme.of(context).colorScheme.onSurfaceVariant,
  ),
),
const SizedBox(height: AppSpacing.md),
LanguagePairSelector(
  selected: selectedLanguage,
  ...
)

3. 저장 경로는 유지하고 Home refresh를 검증한다

저장 로직은 이미 repository write, preferences invalidation, auth session restore 순서로 구성되어 있었습니다. U4는 이 흐름을 새 상태 저장소로 갈라놓지 않고 테스트로 확인합니다.

await ref
    .read(languagePreferencesRepositoryProvider)
    .updateLanguagePreferences(selectedLanguage);
ref.invalidate(languagePreferencesControllerProvider);
await ref.read(authControllerProvider.notifier).restoreSession();
if (sheetContext.mounted) {
  Navigator.pop(sheetContext);
}

4. 문서도 같은 정책을 말한다

`README.md`, `docs/DSL.md`, `.agent/architecture.md`, `mobile/README.md`는 같은 문장을 다른 관점에서 설명합니다. profile default는 future conversation에 쓰이고, existing conversation은 snapshot을 유지한다는 내용이에요.
