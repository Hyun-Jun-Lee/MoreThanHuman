영어 전용 목소리를 언어쌍 중심 UX로 바꾼 작업

U1의 핵심은 기능을 새로 키우는 것이 아니라, 이미 들어온 `LearningLanguageContext`가 사용자가 보는 문장에도 도착하게 만드는 일이에요. 사용자가 답해야 하는 순간에는 target language를 말하고, 회복 안내는 feedback language를 따릅니다.

Background

언어쌍 리팩터 이후 앱에는 네 가지 지원 조합이 생겼어요. `ko -> en`, `en -> ko`, `zh -> en`, `zh -> ko`예요. 하지만 모델이 확장되었다고 해서 제품 경험이 자동으로 확장되지는 않습니다.

U1 이전의 모바일 UX에는 오래된 전제가 남아 있었어요. 온보딩은 “Practice English”라고 말했고, Topic Prep의 첫 답변 입력칸은 언제나 “English로 답하라”고 안내했습니다. 한국어를 배우는 영어권 사용자에게는 이 한 문장만으로도 앱이 자신을 제대로 이해하지 못한다고 느껴질 수 있어요.

핵심 구분 target language는 사용자가 대화에서 연습해야 하는 언어예요. feedback language는 설명과 재시도 안내를 받을 언어예요. U1은 이 두 역할을 모바일 copy에서 섞지 않는 작업입니다.

Native

사용자가 이미 이해하는 언어입니다. selector label과 기본값 추론에 영향을 줍니다.

Target

사용자가 실제로 말하고 써야 하는 연습 언어입니다. 첫 답변 hint가 이 값을 봅니다.

Feedback

오류 설명과 recovery guidance가 따라야 하는 언어입니다.

Intuition

좋은 언어쌍 UX는 매 화면에서 언어를 크게 설명하지 않습니다. 대신 사용자가 행동을 해야 하는 바로 그 문장에만 정확한 언어를 넣습니다. “무엇을 공부하나요?”보다 “지금 어떤 언어로 첫 답변을 써야 하나요?”가 더 중요한 순간이 있어요.

답변 입력칸 hint

이전

모든 Topic Prep ready 화면이 “Type your first answer in English...”라고 말했습니다.

이후

`en -> ko`와 `zh -> ko`는 Korean, `ko -> en`과 `zh -> en`은 English로 안내합니다.

Code

1. 언어쌍 domain helper가 UI 문장을 만든다

`LearningLanguageContext`에 아주 좁은 helper를 추가했습니다. 앱 전체 번역 체계를 만들지 않고, 언어쌍의 역할이 중요한 문장만 이 객체가 책임지게 했어요.

String helperText(String localeCode) {
  final String target = targetLanguage.displayName(localeCode);
  final String feedback = feedbackLanguage.displayName(localeCode);
  return switch (localeCode) {
    'ko' => '대화: $target · 피드백: $feedback',
    'zh' => '对话：$target · 反馈：$feedback',
    _ => 'Conversation: $target · Feedback: $feedback',
  };
}

String firstAnswerHint(String localeCode) {
  final String target = targetLanguage.displayName(localeCode);
  return switch (localeCode) {
    'ko' => '$target로 첫 답변을 입력하세요...',
    'zh' => '请用$target输入你的第一句回答...',
    _ => 'Type your first answer in $target...',
  };
}

2. Topic Prep ready 화면이 응답의 language를 소비한다

준비 카드 자체는 backend가 생성하지만, 입력칸 hint와 접근성 label은 모바일 presentation 영역의 책임입니다. 그래서 `_ReadyTopicPrepView`가 `TopicPrepResult.language`를 받도록 바뀌었습니다.

return _ReadyTopicPrepView(
  card: result.card!,
  language: result.language,
  answerController: _answerController,
  ...
);

AppTextField(
  hintText: language.firstAnswerHint(localeCode),
  semanticLabel: language.firstAnswerSemanticLabel(localeCode),
  ...
);

3. Low-quality recovery는 서버 안내를 우선한다

검색 결과가 부족할 때는 backend가 feedback language로 retry guidance를 줄 수 있어요. U1은 그 서버 문장을 덮어쓰지 않고, 서버가 조용할 때만 fallback copy를 씁니다.

final String message =
    result.retryGuidance ??
    result.quality.retrySuggestion ??
    _TopicPrepFallbackCopy.forLanguage(
      result.language.feedbackLanguage,
    ).message;

4. 온보딩 copy는 중립화한다

온보딩의 큰 약속은 특정 언어 이름보다 제품의 핵심 행동을 말해야 합니다. 그래서 “Practice English”는 “Practice conversation”으로 바뀌었습니다.

description:
    'Practice conversation with news, hobbies, sports, travel, or anything on your mind.',
